# Sleepwing Beta 测试

测试对象：`Packaging/Info.plist` 中 `CFBundleShortVersionString (CFBundleVersion)` 标注的、即将公证发布的那个构建。开始测试前先确认这个版本号和你实际打出来的包一致——不要假设文档里写的版本还是当前要测的版本。

目标不是验证“界面能打开”，而是验证 Sleepwing 能可靠地告诉用户什么时候可以离开、什么时候需要回来，并在不读取工作内容的前提下形成健康闭环。

## 开始

本地开发包：

`.build/perch-app/Sleepwing.app`

首次运行后：

1. 选择眠翼鸟或月尾猫及桌宠大小。
2. 检查 Sleepwing 发现的本机 Agent，仅连接你实际使用的工具。
3. 允许通知，确认 Sleepwing 分开显示授权、横幅和声音状态。
4. 在“连接”页运行“检查全部连接”。本地探针通过只代表配置可达，不代表真实 Agent 任务已经验证。
5. 启动一条真实、无敏感内容的 Agent 任务，确认连接行出现最近真实状态时间。
6. 生成本地诊断报告并在 Finder 中检查：不得出现提示词、回答、代码、完整路径、工具输入、错误正文或会话标识。

产品中没有“状态演练”或“发送测试提醒”。测试必须使用真实生命周期或明确标注的本地连接探针。

## 七个平台矩阵

每个实际安装的平台至少执行适用的开始、等待/权限、完成、失败、退出和移除步骤。

| 平台 | 重点 |
|---|---|
| Claude Code | 权限请求、成功 Stop、StopFailure、SessionEnd 不覆盖失败 |
| Cursor IDE | `beforeSubmitPrompt`、响应、停止与窗口聚焦 |
| Cursor CLI | 独立验证，不继承 IDE 结论。注意：代码里 IDE 和 CLI 目前共用同一份 `~/.cursor/hooks.json` 配置，没有分开处理，测试时不要因为配置共享就假设两边行为一致，必须分别确认两个界面各自真的触发了 Hook 事件 |
| ChatGPT / Codex | ChatGPT 产品身份、Codex 生命周期、精确返回本地任务 |
| OpenCode | 官方插件加载、权限、成功完成、失败恢复、移除 |
| Gemini CLI | 开始、权限、完成、退出与配置还原 |
| TRAE / TRAE CN | 两种配置路径、真实 App 聚焦、完成与移除 |
| pi coding agent | `agent_start`、`agent_settled`、退出与扩展移除 |

普通 ChatGPT 对话没有 Codex 任务生命周期时，Sleepwing 不得显示其正在工作。

## 二十分钟核心回归

| 测试 | 预期 |
|---|---|
| 打开设置 | 原生标题栏只在中央显示 `Sleepwing`，内容区顶部只有一行紧凑四段导航，不重复显示品牌名或图标；字体不换行、不堆叠成两行；桌宠保持可见 |
| 开启“任务运行时保持系统唤醒” | 设置页出现连续时长上限调节器（默认 4 小时，可调 1–12）；启动一个真实 Agent 任务后屏幕实际不熄屏（不只是系统不睡眠）；菜单栏面板常驻显示开关和实时状态，无需打开设置即可开关；连续达到上限后自动释放；低电量模式/低电量警告时自动暂停并在菜单栏显示暂停原因 |
| 切换角色、尺寸和层级 | 桌宠实时变化，重启后保留 |
| 连续切换内置及自定义角色 | 首轮载入后动作稳定；替换同路径素材后展示新版本；空闲 CPU 不因 30fps 无效刷新持续偏高 |
| 启动一个 Agent | 菜单栏和桌宠显示确定的平台名、状态和时间 |
| 同时启动两个 Agent | 始终只有一只桌宠，健康机会时间只累计一次 |
| 一个 Agent 等待、另一个工作 | 等待用户的任务优先，健康提醒暂停 |
| 点击需要处理的任务 | 有精确路由的平台回到具体任务；其余平台诚实地只打开 App |
| 暂时静音一个任务 | 任务仍可见，但不再抢占桌宠；生命周期结束后静音自动清除 |
| Agent 失败 | 显示确定平台，不庆祝，不展示错误正文，过期后清理 |
| Agent 完成 | 短暂庆祝后回到其他活跃状态或休息 |
| 达到健康阈值 | 出现一个有明确时长的健康动作 |
| 完成 / 稍后 / 跳过 | 分别记录；稍后在十分钟后重新出现且不重复 |
| 稍后期间重启 Sleepwing | 到期后仍只出现一次；若 Agent 正在等用户或处于免打扰时段则顺延 |
| 锁定屏幕后达到阈值 | 不把桌宠误判为可见渠道；通知横幅可用时改走系统通知 |
| 关闭横幅但保留通知授权 | Sleepwing 明确提示横幅不可见并提供系统设置入口 |
| 隐藏再显示桌宠 | 隐藏状态保持；重新显示后回到可见屏幕 |
| 退出 Sleepwing 后运行 Agent | Agent 自身不被阻塞，Hook 静默返回 |
| 重新启动 Sleepwing | 接收器恢复，下一条真实事件可达 |
| 移除连接 | 仅删除 Sleepwing 管理的配置，其他 Hook 保留 |

## 桌面环境回归

- 在浅色、深色和复杂壁纸上检查状态卡与符号。
- 拔插显示器并改变排列，桌宠至少 40% 保持在可用画面内。
- 切换 Spaces 和全屏，确认没有重复桌宠。
- 锁定、解锁、睡眠和唤醒后确认桌宠恢复且不抢键盘焦点。
- 打开系统“减少动态效果”，所有状态仍可区分。
- 设置窗口打开期间拖动桌宠，关闭设置后位置仍保存。

## Pet Studio 回归

1. 安装 Sleepwing Pet Skill。
2. 确认只有检测到 Codex 时才显示 Codex 专用创建入口。
3. 导入一个使用 `--require-visual-qa` 打包且 `qa-summary.json` 通过的
   Motion v2 `.perchpet` 包。
4. 拒绝缺少/伪造视觉验收、错误尺寸、符号链接、越界路径、缺少 alpha
   或过大文件；旧版本地已安装角色仍可使用，但必须标注“未记录视觉验收”。
5. 选择自定义桌宠，检查休息、工作、等待、完成、拖动和方向状态。
6. 删除或破坏已选包后，Sleepwing 应回退到月尾猫。
7. 用 `ditto` 压缩并解压最终 `.app` 到源码目录之外；从解压副本打开“连接”和 Pet Studio，确认品牌资源、双语文案、两只内置角色和 App 自带的包校验器均可用，且二进制不包含构建机绝对路径。

## 数据与回滚

- 本地数据：`~/Library/Application Support/Perch/data.json`
- Relay：`~/Library/Application Support/Perch/bin/perch-hook`
- 配置备份：原配置旁的 `.perch-backup-<timestamp>-<id>`

Bug 报告不得附带提示词、代码或私有文件。优先提供 Sleepwing 截图、平台名称与版本、发生时间以及允许列表诊断报告。

## 五个测试反馈问题

1. 不解释产品时，你认为桌宠正在告诉你什么？
2. Agent 工作时你敢离开屏幕吗？为什么？
3. 健康提醒太早、太晚、太频繁，还是刚好？
4. Agent 需要你时，你能否立即知道要回到哪个任务？
5. 哪一步仍然要求你理解 Hook、CLI 或配置文件？
